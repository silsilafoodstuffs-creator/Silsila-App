# سجل عناصر القوائم ومسارات التوجيه — 2026-11-11

المصدر: `lib/erp/erp_dashboard_screen.dart` في main؛ شاشة التقارير `lib/erp/screens/erp_report_center_screen.dart`.
هذه مصفوفة جرد ثابتة مولدة من الكود، وليست إثبات اختبار لكل route أو اتصال قاعدة بيانات.

- عناصر القوائم: 485
- أسماء الصفحات الفريدة: 468
- عدد الوحدات: 15
- عناصر مجموعة التقارير: 141
- أسماء التقارير التي تمر إلى قارئ قاعدة البيانات: 59
- مفاتيح مصادر التقارير الموجودة في `_sources`: 52، منها 45 فقط تتقاطع مع أسماء `_isDatabaseReport`
- أسماء من قائمة `_isDatabaseReport` بلا مصدر في `_sources`: 14
- التوجيهات العامة: يتم استخدام `_workspace()` لكل عنصر لم يطابق فرعًا مخصصًا؛ يلزم فحص نوع النموذج والجدول لكل حالة.

## تعريف الوجهات
- **توجيه مخصص**: شرط محدد في لوحة التحكم يفتح شاشة مستقلة أو شاشة مشتركة بمدخلات.
- **HR**: `ErpHrAffairsScreen` يوزع أسماء الصفحات إلى Employee Master وStructure وAttendance وLeave وPayroll وCatalog، وما عدا ذلك إلى `ErpHrRecordsScreen`.
- **Business Suite**: `ErpBusinessSuiteScreen` يحدد الوحدة ونوع النموذج من اسم الصفحة. هذا لا يعني أن كل page له جدول مستقل؛ بعض الأنواع تحفظ في `erp_business_suite_records` وبعضها يزامن إلى جداول تشغيلية.
- **E-invoice**: `ErpEinvoiceScreen` يستخدم initialView.
- **Report Center**: `ErpReportCenterScreen` قارئ read-only. وجود اسم التقرير في `_sources` يعني تحديد مرشح مصدر فقط، وليس اكتمال المعادلة أو التجميع أو المصالحة.
- **Workspace عام**: `_workspace()`؛ يجب عدم اعتبار السجل العام بديلًا عن كيان تشغيلي متعدد البنود أو تقرير محسوب.

2. عدم ترك صفحات الحركة أو التقارير الحساسة تسقط إلى `_workspace()` بلا اعتماد تصميم صريح.
3. لكل تقرير تعريف Query/RPC/SQL view خاص بالمعادلة والفلاتر والتجميع والتسوية؛ لا يكفي `select *`.
4. لكل شاشة Business Suite تحديد table + line table + RPC posting + reversal + audit log.
5. يجب معالجة التكرارات الـ17 في أسماء القوائم: إما alias مقصود موثق أو إزالة تكرار من القائمة.
6. توحيد القوائم المتداخلة للموارد البشرية وعلاقات العملاء بعد تحديد مصدر الحقيقة لكل شاشة.
