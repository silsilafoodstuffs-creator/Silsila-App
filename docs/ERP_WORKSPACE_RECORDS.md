# حفظ سجلات مساحة العمل في سلسلة ERP

## ما الذي تغير؟
- أضيفت خدمة `ErpWorkspaceRecordsService` لقراءة السجلات القابلة للتهيئة وحفظها وتعديلها وحذفها في Supabase بحسب الشركة والشاشة.
- شاشة مساحة العمل العامة تحاول تحميل سجلات الشاشة من قاعدة البيانات بعد تحديد الشركة، وتعرض قائمة فارغة عند نجاح التحميل وعدم وجود سجلات بدل عرض أمثلة الواجهة.
- أزرار الإضافة والتعديل والحفظ والحذف تستخدم الخدمة عند توافر شركة نشطة؛ وتظهر رسالة واضحة إذا تعذر الحفظ.
- لا تُستخدم هذه الجداول كبديل للجداول المحاسبية أو المخزنية أو سجلات الرواتب والمستندات التشغيلية المتخصصة.

## إعداد قاعدة البيانات
نفّذ الملفات بالترتيب في Supabase SQL Editor، بعد مراجعة المشروع:
1. `supabase/erp_schema.sql`
2. `supabase/erp_security_membership.sql`
3. `supabase/erp_workspace_records.sql`

يجب أن يكون المستخدم مسجل الدخول وله عضوية نشطة في الشركة. سياسات RLS تمنع الوصول خارج الشركات المصرح بها. الحذف الدائم مقصور على مالك الشركة أو مديرها، لذلك قد يرفض الخادم الحذف لأدوار أخرى حتى لو ظهر الزر.

## حدود البيانات
هذا المسار مخصص للسجلات العامة التي لم يُنشأ لها نموذج متخصص بعد. لا تُدخل أرصدة محاسبية أو مستندات قانونية أو رواتب في هذا الجدول؛ استخدم الشاشات والجداول المخصصة لهذه الوظائف. بيانات الأمثلة في الواجهة ليست بيانات فعلية ولا تُرفع باعتبارها كذلك.

## حالة التحقق
نجاح بناء Flutter Web لا يثبت أن هذه الترحيلات طُبقت على مشروع Supabase. يجب تطبيق SQL وتسجيل الدخول ثم اختبار القراءة والإضافة والتعديل والحذف بحسابات ذات صلاحيات مختلفة قبل التشغيل الفعلي.
