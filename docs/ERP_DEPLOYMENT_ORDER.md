# دليل تجهيز قاعدة بيانات سلسلة ERP

هذا الدليل يحدد تسلسلًا عمليًا لمراجعات وترحيلات Supabase. **لا تنفذ ملفات SQL دفعة واحدة على قاعدة إنتاج**؛ ابدأ بقاعدة اختبار/نسخة احتياطية، وافحص نتيجة كل ملف قبل الانتقال للذي يليه. هذه الملفات موجودة في GitHub ولا يعني وجودها أنها طُبقت على مشروع Supabase.

## المرحلة 1: المخططات الأساسية

1. `supabase/erp_schema.sql`
2. `supabase/erp_operations_schema.sql`
3. `supabase/erp_master_data_schema.sql`
4. `supabase/erp_hr_schema.sql`
5. `supabase/erp_hr_attendance_schema.sql`
6. `supabase/erp_cash_vouchers_schema.sql`

إذا توقف ملف بسبب جدول أو عمود مفقود، لا تتجاوز الخطأ ولا تكمل باقي الترحيلات؛ راجع الاعتماد المفقود أولًا.

## المرحلة 2: سلامة البيانات والقيود

7. `supabase/erp_account_integrity.sql`
8. `supabase/erp_account_tree_metrics.sql`
9. `supabase/erp_journal_workflow.sql`
10. `supabase/erp_security_membership.sql`
11. `supabase/erp_fiscal_period_workflow.sql`

ملف العضويات يضيف سياسات RLS. لا تفتح الجداول للمستخدمين قبل إنشاء عضوية الشركة الصحيحة للمستخدمين المصرح لهم. إنشاء أول شركة وعضوية مالكها إجراء إداري منفصل؛ لا تضع مفتاح `service_role` في Flutter.

## المرحلة 3: دورات التشغيل

12. `supabase/erp_journal_reversal.sql`
13. `supabase/erp_ledger_reports.sql`
14. `supabase/erp_inventory_workflow.sql`
15. `supabase/erp_operations_workflow.sql`
16. `supabase/erp_cash_voucher_workflow.sql`
17. `supabase/erp_operational_accounting.sql`
18. `supabase/erp_payroll_workflow.sql`
19. `supabase/erp_master_data_integrity.sql`
20. `supabase/erp_price_list_workflow.sql`
21. `supabase/erp_price_resolution.sql`
22. `supabase/erp_movement_audit.sql`

- `erp_operational_accounting.sql` يضيف خريطة حسابات الأستاذ ودالة إنشاء القيد المحاسبي للمستندات التشغيلية المرحلة. لا تنفذه قبل اكتمال القيود والمخزون والمبيعات والمشتريات وعضويات الشركات.

تحتاج هذه المرحلة مراجعة فعلية للأعمدة والفهارس وسياسات RLS الموجودة في نسخة قاعدة البيانات المستهدفة؛ خصوصًا قبل اعتماد أو ترحيل مستندات مالية أو مخزنية. قد تختلف الحاجة لترتيب ملفين إذا تغيرت تبعيات المخطط، لذا لا تعتبر القائمة بديلًا عن قراءة الأخطاء الناتجة عن SQL Editor.

## المرحلة 4: فحص ما بعد الترحيل

23. شغّل `supabase/erp_preflight_check.sql` في SQL Editor. هذا فحص قراءة فقط يعرض وجود الجداول والدوال وحالة RLS وعدد السياسات، ولا ينشئ أو يعدّل بيانات.
24. راجع كل صف بحالة «غير موجود»، وتأكد من أن كل جدول ERP يحتوي على RLS وسياسات مقصودة، وأن دوال الترحيل لا يستطيع تنفيذها إلا الدور المناسب.
25. أنشئ شركة اختبار، وفرعًا، وفترة مالية مفتوحة، وشجرة حسابات متوازنة، وحسابات نقدية، ومخزنًا وصنفًا وطرفًا تجريبيًا. استخدم مستخدمين بأدوار مختلفة للتأكد من عزل الشركات والصلاحيات.
26. لا تبدأ اختبارات التكامل أو بناء APK إلا بعد اكتمال التطوير وموافقة المستخدم على بدء الاختبارات.

## تنبيهات محاسبية

- لا تُدخل أرصدة افتتاحية للعملاء أو الموردين دون ربطها لاحقًا بقيود افتتاحية متوازنة وحسابات الأستاذ العام. قيمة `opening_balance` في بطاقة الطرف وحدها لا تُعد قيدًا محاسبيًا.
- ترحيل فاتورة مشتريات أو مبيعات يجب أن ينتج أثر المخزون والقيد المحاسبي المناسبين دون تكرار؛ لا تعتبر نجاح تغيير حالة المستند كافيًا.
- عكس القيد ينشئ قيدًا عكسيًا منفصلًا ولا يمحو القيد الأصلي.
- التحويل بين خزائن من فرعين مختلفين موقوف في التحقق الحالي إلى أن يُبنى إجراء تحويل بين الفروع يحدد حسابات المقاصة والأثر المحاسبي.
- عند فشل أي ترحيل، احتفظ بنص الخطأ كاملًا دون نشر مفاتيح أو بيانات شخصية؛ لا تكرر التنفيذ قبل فهم ما إذا كانت العملية قد نجحت جزئيًا أو كليًا.

## ملاحظة الحالة الحالية

ملفات SQL والشاشات تُحفظ في مستودع GitHub. لم يتم تطبيق الترحيلات على Supabase ولم تُشغّل اختبارات أو عملية بناء APK في سياق العمل الحالي.
