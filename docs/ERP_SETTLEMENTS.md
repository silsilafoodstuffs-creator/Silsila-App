# مستندات المقبوضات والمدفوعات — سلسلة ERP

## الملفات
- `supabase/erp_settlement_schema.sql`: جداول سندات القبض والصرف وتخصيص السندات على فواتير البيع والشراء.
- `lib/erp/services/erp_settlement.dart`: نموذج محلي للتحقق من السند والتخصيصات وتجهيز بياناته.

## ترتيب التطبيق
1. تطبيق `supabase/erp_schema.sql`.
2. تطبيق `supabase/erp_operations_schema.sql`.
3. تطبيق `supabase/erp_settlement_schema.sql`.
4. إضافة سياسات RLS المقيدة بالشركة والفرع والمستخدم قبل إتاحة أي قراءة أو كتابة من التطبيق.

## أنواع السندات
- قبض من عميل.
- صرف لمورد.
- رد مبلغ لعميل.
- رد مبلغ من مورد.
- قبض آخر أو صرف آخر.

## ضوابط مطلوبة قبل التشغيل الفعلي
- التحقق من انتماء الطرف والخزينة والفرع إلى الشركة نفسها في الخادم.
- منع تخصيص مبلغ يتجاوز قيمة السند أو الرصيد المتبقي على الفاتورة.
- اعتماد السند وترحيله في معاملة قاعدة بيانات واحدة، وإنشاء قيد محاسبي متوازن مرة واحدة فقط.
- منع تعديل أو حذف السند المرحّل، وتوفير عكس محاسبي موثق بدلًا من ذلك.
- مطابقة نوع السند مع نوع الطرف والمستند، ومنع إعادة الترحيل عند إعادة إرسال الطلب.
- لا تخزن أرقام بطاقات كاملة أو بيانات دخول بنكية حساسة.

## الحالة الحالية
هذه الملفات تمثل مخطط قاعدة بيانات ونموذج تحقق محليًا. لم يتم تطبيق SQL على Supabase ولم يتم توصيل النموذج بواجهات المستخدم أو API خلفي. لا تعتبر السندات مؤثرة في أرصدة الخزائن أو الفواتير أو القيود المحاسبية حتى تُنفذ قواعد الترحيل الموثوقة.
