# سلسلة Silsila

تطبيق تجارة وتوزيع المواد الغذائية بالجملة مبني باستخدام Flutter وDart، مع Supabase للمصادقة وقاعدة البيانات.

## الهوية
- الاسم: سلسلة Silsila
- الشعار: سلسلة .. بنربط السوق ببعضه
- الألوان: بنفسجي `#3E007D`، برتقالي `#FFA015`، وردي `#FF27C3`
- اتجاه الواجهة: RTL

## المكونات
- تطبيق Flutter للهواتف والويب.
- مصادقة Supabase باستخدام رقم الهاتف وكلمة المرور ورمز SMS عند تفعيل ذلك في Supabase.
- خدمات حسابات العملاء والموردين والمندوبين والطلبات والمنتجات والسلة والمفضلة والمحفظة والإشعارات والدعم.
- ملفات قاعدة البيانات موجودة في مجلد `supabase/`.

## إعداد قاعدة البيانات

استخدم [دليل التهيئة النهائي](supabase/APPLY_MIGRATIONS_FINAL.md) لتطبيق ترحيلات Supabase المصححة بالترتيب الكامل، بما فيها تشديد سياسة إنشاء الشحنات في الترحيل 21، وتعيين العنوان الافتراضي ذريًا في الترحيل 22، وحفظ العنوان الافتراضي أو تعديله ذريًا في الترحيل 23. لا تشغّل النسخ القديمة من ملفات checkout والتوافق المشار إليها في الدليل.

## إعداد مصادقة الهاتف
1. افتح إعدادات Authentication في مشروع Supabase.
2. فعّل Phone authentication.
3. اضبط مزود SMS وفق إعدادات مزود الخدمة الذي تستخدمه.
4. اضبط سياسات OTP ومدة صلاحية الرمز.
5. لا تضع مفاتيح `service_role` أو أي سر إداري داخل تطبيق Flutter؛ استخدم المفتاح العام فقط مع RLS وسياسات قاعدة بيانات صحيحة.

## إعداد Flutter
1. ثبّت Flutter بإصدار مستقر متوافق مع قيود `pubspec.yaml`.
2. نفّذ `flutter pub get`.
3. راجع وجود الأصول والخطوط المشار إليها في `pubspec.yaml`.
4. أنشئ إصدار Android من خلال GitHub Actions أو بيئة Flutter المحلية بعد اكتمال مرحلة التطوير.

## ملاحظات تشغيلية
- لا تعتبر أسعار المنتجات التجريبية في الواجهة أسعارًا تجارية معتمدة.
- تشغيل ترحيلات SQL على GitHub لا يطبقها تلقائيًا على مشروع Supabase؛ يجب تشغيلها يدويًا من SQL Editor بالترتيب أعلاه.
- إنشاء الطلبات عبر `place_supplier_order` يقرأ الأسعار من قاعدة البيانات ويحفظ الطلب وبنوده داخل معاملة واحدة لكل مورد.
- رفع الملفات يعتمد على الحاويات والسياسات الموجودة في `supabase/05_storage_policies.sql`.
- ملفات SQL المحفوظة في GitHub لا تُطبق تلقائيًا على مشروع Supabase؛ شغّل الترحيلات بالترتيب من SQL Editor.
- يجب اعتماد حركات المحفظة وتعديل الأرصدة على الخادم، مع تسجيل واضح للمعاملات ومنع التكرار.
- لا تنفذ تحويلات مالية أو تضف رصيدًا اعتمادًا على بيانات يرسلها العميل مباشرة.
- قبل الإطلاق، راجع سياسات RLS، صلاحيات الأدوار، سياسة الخصوصية، وشروط الاستخدام، ثم نفّذ الاختبارات النهائية.


## إعداد Supabase

راجع [ترتيب ترحيلات Supabase النهائي](supabase/APPLY_MIGRATIONS_FINAL.md) وشغّل ملفات SQL يدويًا بالترتيب الموضح هناك قبل تفعيل وظائف قاعدة البيانات.

## قائمة مراجعة ما قبل الإطلاق

### قاعدة البيانات والأمان
- [ ] تطبيق جميع ملفات SQL الواردة في دليل الترحيلات النهائي على مشروع Supabase الصحيح، بالترتيب، والتحقق من نتيجة كل ملف.
- [ ] التأكد من تفعيل RLS على الجداول التي تحتوي بيانات المستخدمين أو الطلبات أو الأرصدة.
- [ ] اختبار الوصول بحساب عميل ومورد ومندوب وشركة شحن وإدارة نشاط، والتأكد من أن كل دور لا يرى إلا البيانات المصرح بها.
- [ ] التأكد من أن أسعار المنتجات وإجماليات الطلبات وحركات المحفظة تُحسب أو تُتحقق منها على الخادم، لا من قيم الواجهة فقط.
- [ ] مراجعة إعدادات Phone OTP ومزود الرسائل وحدود إرسال الرموز قبل إتاحة استعادة كلمة المرور للمستخدمين.

### التطبيق والإصدار
- [ ] التحقق من وجود ملفات المنصات المطلوبة وإعدادات معرّف التطبيق قبل طلب إصدار جديد.
- [ ] الحفاظ على مفتاح توقيع Android نفسه لكل تحديث؛ لا ترفع ملف keystore أو كلمات مروره إلى المستودع.
- [ ] مراجعة صلاحيات Android وملفات إعداد الويب، والتأكد من عدم تضمين مفاتيح إدارية أو بيانات اعتماد سرية.
- [ ] تجربة تسجيل الدخول والتسجيل واستعادة كلمة المرور، وإضافة العناوين، والسلة، وإتمام الطلب، والإشعارات، والشحن بحسابات تجريبية.
- [ ] إجراء البناء والاختبارات النهائية فقط بعد انتهاء تعديلات التطوير ومراجعة الإعدادات.

> وجود ملفات SQL في المستودع لا يعني تطبيقها على قاعدة Supabase الحية. لا يُعدّ التطبيق جاهزًا للإطلاق حتى تُنفّذ هذه المراجعات على بيئة الاختبار والبيئة المستهدفة.
