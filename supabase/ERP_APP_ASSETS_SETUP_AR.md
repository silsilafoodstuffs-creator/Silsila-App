# إعداد رفع صور تطبيقات سلسلة ERP

## المتطلبات
طبّق هذه الملفات في SQL Editor داخل مشروع Supabase نفسه، وبالترتيب:

1. `erp_schema.sql`
2. `erp_security_membership.sql`
3. `erp_app_management_schema.sql`
4. `erp_app_asset_storage_policies.sql`
5. `erp_app_assets_edit_policy.sql`

لا يكفي حفظ ملفات SQL في GitHub؛ يجب تنفيذها في قاعدة Supabase الفعلية حتى تُنشأ الجداول وسياسات التخزين.

## ما الذي تفعله شاشة إدارة الصور؟
- تتيح اختيار صورة من الجهاز عبر الويب أو الهاتف.
- تدعم JPG وPNG وWEBP وGIF بحد أقصى 8 ميجابايت.
- ترفع الملف إلى bucket خاص اسمه `erp-app-assets` بمسار يحتوي على معرّف الشركة والتطبيق ونوع الصورة.
- تسجّل مسار الملف واسمه ونوعه وحجمه ووصفه ومعرّف العنصر الاختياري في `erp_app_assets`.
- تعرض الصور باستخدام رابط مؤقت موقّع، ولا تحفظ الرابط المؤقت باعتباره هوية الصورة.
- تتحقق سياسات التخزين وقاعدة البيانات من عضوية الشركة وصلاحية المالك/المدير.

## الاستخدام
1. سجّل الدخول بمستخدم Supabase لديه عضوية شركة نشطة.
2. افتح «إدارة التطبيقات» واحفظ سجل التطبيق «سلسلة» للشركة أولًا.
3. افتح «إدارة الشعار والصور» أو «إدارة صور الأصناف والفئات» أو «إدارة صور الموردين والعملاء».
4. اختر نوع الصورة، ويمكن إدخال معرّف الصنف/الطرف والوصف ثم اختيار الصورة ورفعها.
5. تحقق من ظهور السجل في القائمة. إن ظهرت رسالة صلاحيات أو جدول غير موجود، راجع تطبيق ملفات SQL بالترتيب أعلاه.

## بيانات إنتاج حقيقية
لا يحتوي هذا الملف على أسماء عملاء أو موردين أو أرقام هواتف مفترضة. أدخل البيانات التي تم التحقق منها من سجلات الشركة أو المصادر الرسمية، ولا تعتبر بيانات المثال أو الدليل العام عملاء متعاقدين. لا تضع مفاتيح `service_role` في التطبيق أو GitHub.
